## ⚠️ УРОКИ (дорого дались — не повторять)

1. **Мобильное проверять ТОЛЬКО на реальном телефоне.**
   Узкое окно браузера на компьютере и эмуляция DevTools ВРУТ — заголовок
   влезал в узком окне, но на настоящем экране переносился и налезал на вывеску.
   Проверять через Netlify (после деплоя) или локальный Network-адрес
   (`npm run dev` печатает `Network: http://192.168.x.x:3000`), открыв с телефона
   в той же Wi-Fi. Эмуляция hover тоже врёт — та же история была с tooltip.

2. **НЕ править один файл параллельно руками (Zed) и через Claude Code.**
   Отсюда весь хаос: «This file has changed on disk», потерянные правки,
   откаты, «всё слетело», сломанная сборка. Версии дерутся, Overwrite/Discard
   теряет часть изменений. Правило: ОДИН источник правок за раз.
   - мелкие точечные правки → руками в Zed, по одной, с `Ctrl+S` после каждой;
   - крупные задачи → Claude Code, а файл в Zed НЕ трогать (только смотреть).
   Если Claude Code правил файл — перед ручной правкой закрыть и переоткрыть
   файл в Zed, чтобы видеть актуальную версию с диска.

3. **Коммитить точки сохранения по ходу.** Свежий коммит в гите = всегда есть
   куда откатиться. Сегодня это спасало.

## Задача A — Масштаб / высота hero (ОТЛОЖЕНО)

При отдалённом масштабе hero не заполняет экран целиком, снизу вылезает About.
Структурная правка (высота секции, object-fit) — проверять на нескольких
размерах И на реальном телефоне. Со свежей головой.

## Задача B — Разная высота текста hero vs Plan Your Stay (мелочь, некритично)

hero `min-h-[80vh]`, stay `min-h-[75vh]` — текст стоит на чуть разной высоте.
Никто кроме автора (со скриншотами рядом) не заметит. Если захочется идеала —
привести к одной min-h. Не срочно.
