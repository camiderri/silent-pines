# Silent Pines — Roadmap / список задач

Рабочий файл для себя. Не часть «мира» сайта — просто чтобы ничего не потерялось
и можно было вернуться на свежую голову.

## ⚠️ УРОКИ (дорого дались — не повторять)

1. **Мобильное проверять ТОЛЬКО на реальном телефоне, в инкогнито.**
   Узкое окно браузера и эмуляция DevTools ВРУТ. Плюс обычная вкладка держит
   СТАРЫЙ КЭШ — после смены картинок показывала пустые рамки, хотя всё работало.
   Инкогнито = всегда свежая версия, без кэша. Проверять там.

2. **НЕ править один файл параллельно руками (Zed) и через Claude Code.**
   «file changed on disk», потерянные правки, откаты. ОДИН источник за раз.
   Если Claude Code правил — закрыть и переоткрыть файл в Zed перед ручной правкой.

3. **Кэш браузера обманывает.** «Картинки не грузятся / задержка» на СВОЁМ телефоне
   часто = старый кэш, а не поломка. Проверять в инкогнито. У новых посетителей
   кэша нет — они видят свежую версию сразу.

4. **Вес изображений критичен для мобильного/Instagram.** Генераторные картинки
   по 1-2 МБ. Жать в WebP q82 → вес падает ~90% без потери качества. AVIF/srcset/
   4 размера НЕ нужны для маленького сайта. Сделано: 18 МБ → 2 МБ.

5. **Netlify: ~300 бесплатных сборок (кредитов) в месяц, обновляются 1 числа.**
   Каждый push = одна сборка = расход кредитов. НЕ пушить каждую мелочь отдельно!
   Копить правки локально, проверять на localhost, пушить ПАЧКОЙ (один push на
   несколько правок). За день множества мелких пушей сожгли 75% месячного лимита.

6. **Загрузка фоновых картинок (hero) на мобильном:** background-image грузится
   не приоритетно → видно «недогруженное» состояние. Лечится: тёмный
   `backgroundColor` под hero (заглушка в тон, текст читается сразу) +
   `ReactDOM.preload("/images/hero.webp", { as: "image" })` для приоритета
   (в Next.js App Router `<link rel=preload>` в JSX не работает — только ReactDOM.preload).
